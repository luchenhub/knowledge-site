HTML 表单有哪些考点？ ​

表单是「采集数据 → 校验 → 提交」的完整链路：<form> 决定往哪发、怎么编码；控件负责类型与 name；浏览器与 JS 提供约束校验与 FormData。下面按面试常考顺序拆。

一、form 与 enctype ​

html
<form action="/api/login" method="post" enctype="application/x-www-form-urlencoded">
  <!-- 控件 -->
  <button type="submit">提交</button>
</form>
属性作用常见默认
action提交 URL当前文档 URL
methodget / post / dialog 等get
enctype请求体编码方式application/x-www-form-urlencoded
target提交响应的浏览上下文_self
novalidate关闭浏览器原生校验-
autocomplete是否参与自动填充on

enctype 三种：

值使用场景
application/x-www-form-urlencoded默认；普通键值对，& 连接
multipart/form-data含 <input type="file"> 时必用
text/plain几乎不用，调试或邮件客户端场景偶见

只有 method 为 POST（且未用 fetch 自定义 body）时，enctype 才对经典表单提交有意义；GET 的查询串编码规则不同。

二、控件一览 ​

元素作用
<input>单行输入，具体行为由 type 决定
<textarea>多行文本
<select> + <option>（+ <optgroup>）下拉；加 multiple 可多选
<button>按钮；type 为 submit / reset / button，在表单内默认 submit
<fieldset> + <legend>分组与标题，利于无障碍与样式
<datalist>与 input 搭配做「可输入的下拉建议」

提交时：带 name 的成功控件才会进入请求（disabled 的控件不参与）。

三、input 的 type 速查 ​

文本与密码：text、password、search、email、url、tel

选择与开关：radio（同 name 互斥）、checkbox（同 name 可多项，提交时多为同名多值）

数值与范围：number、range

日期时间：date、time、datetime-local、month、week（具体 UI 因浏览器/系统而异）

其它：file（常配 accept、multiple）、hidden、color、image（坐标提交，少见）

按钮型：submit、reset、button —— 更推荐用 <button>，可包图标与文字，语义更清晰。

html
<input type="radio" name="gender" value="m" /> 男
<input type="checkbox" name="hobby" value="code" />
<input type="checkbox" name="hobby" value="music" />

<select name="city">
  <option value="">请选择</option>
  <option value="bj">北京</option>
</select>

四、约束校验与 CSS ​

常用 HTML 属性（浏览器原生 Constraint Validation）：

属性说明
required必填
min / max / step数值、日期等
minlength / maxlength文本长度
pattern正则（整条字符串匹配）
title与 pattern 等配合，作提示文案

JavaScript API（挂在控件上）：

js
el.checkValidity();       // 是否通过约束
el.reportValidity();      // 不通过时弹出浏览器提示
el.setCustomValidity(''); // 清空自定义错误；非空字符串表示自定义失败原因

CSS 伪类：:valid、:invalid、:optional、:required、:user-valid / :user-invalid（用户交互后再判，比裸用 :invalid 更不易一进来就全红）

css
/* 注意：<input> 是替换元素（replaced element），不由 CSS 生成内容盒子，因此不支持 ::before/::after 伪元素 */
input:user-invalid {
  border-color: #c62828;
}

type="email"、url 等会多一层类型约束；pattern 与内置类型同时存在时，都需满足。

五、label 与无障碍 ​

html
<label for="user">用户名</label>
<input id="user" name="username" autocomplete="username" />

<label>
  邮箱
  <input type="email" name="email" />
</label>
  • for + id：点击文字聚焦控件，屏幕阅读器可读关联。
  • 包裹写法：省略 for，结构紧凑；注意嵌套不要和 for 混用冲突。

无 label 时，仅靠 placeholder 不能替代标签（失焦后提示消失，无障碍不足）。

六、GET 与 POST 对比 ​

对比GETPOST
数据位置URL 查询串请求体（经典表单）
长度受 URL 长度限制（浏览器/服务端）仍可能受服务端/网关限制，不是无限
缓存与历史易进历史、易出现在 Referer、服务端日志相对少出现在 URL 里
典型用途搜索、筛选、幂等查询登录、下单、文件上传

安全：防窃听靠 HTTPS；GET 与 POST 在 TLS 下都会加密传输。差别主要在 URL 是否暴露（书签、日志、代理）、是否适合幂等/缓存语义（REST 里常约定 GET 不改状态）。

在 SPA 里常用 preventDefault() 后自行 fetch；若用 multipart/form-data，fetch 的 body 可直接传 FormData，不要再手动设 Content-Type（浏览器会带 boundary）。

七、JavaScript：submit 与 FormData ​

js
form.addEventListener('submit', (e) => {
  e.preventDefault();
  const fd = new FormData(form);
  fd.append('extra', 'value');
  fetch(form.action, { method: form.method, body: fd });
});
  • FormData(form)：收集带 name 的控件；文件字段一并包含。
  • 同名多值（如多选 checkbox）：fd.getAll('hobby')。

八、进阶拾遗 ​

  • form 属性：控件可写在 <form> 外，用 form="某form的id" 仍参与该表单提交。
  • button 的 formaction / formmethod：可覆盖所在 <form> 的 action、method（仅对该次提交）。
  • enter 提交：单文本框的 form 里按回车常触发表格提交；多控件时注意默认行为与 button type。

九、面试小结 ​

  1. enctype：multipart/form-data 配文件上传；默认 urlencoded。
  2. 成功控件：有 name、非 disabled 才会提交。
  3. radio / checkbox / select：radio 同 name 互斥；checkbox 同名多值。
  4. 校验：required、pattern、min/max + checkValidity / reportValidity / setCustomValidity。
  5. label：关联控件与无障碍，别只靠 placeholder。
  6. GET vs POST：数据在 URL 还是 body、语义与缓存差异；安全重点在 HTTPS 与是否进 URL。
  7. 拦截提交：preventDefault + FormData + fetch；multipart 时 FormData 不要手写 boundary。
