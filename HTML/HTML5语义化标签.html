HTML 语义化是面试中极其高频的考点，但大多数候选人只能列举标签，真正能说清楚"为什么"和"影响面"的人并不多。下面从三个层次来拆解。

一、先看"不语义化"会发生什么 ​

用 div 堆砌一切是最常见的反模式：

html
<!-- 反面教材：全是 div -->
<div class="header">
  <div class="nav">...</div>
</div>
<div class="main">
  <div class="article">
    <div class="title">...</div>
  </div>
</div>
<div class="footer">...</div>

对浏览器来说，这些 div 毫无区别——它不知道哪里是导航、哪里是主内容、哪里是页脚。

二、HTML5 核心语义化标签全景 ​

标签细节详见：https://developer.mozilla.org/zh-CN/docs/Web/HTML/Reference/Elements

三、为什么要用语义化标签——四个维度 ​

这是面试官真正想听的部分，纯背标签列表是不够的。

1. 无障碍（Accessibility）

屏幕阅读器（如 VoiceOver、NVDA）依赖 HTML 语义来生成"地标导航"。<nav> 会被读出为"导航区域"，用户可以直接跳转；而 <div class="nav"> 对辅助技术来说与普通容器无异。这对残障用户来说是功能性差异，不是体验差异。

2. SEO

搜索引擎爬虫理解语义结构，<h1>~<h6> 的层级、<article> 的范围、<time datetime="2024-01-01"> 的机器可读时间，都能帮助理解页面结构。<strong> 等强调标签对排名的直接加权很有限，远不如标题层级、正文质量与外链等因素。

3. 可维护性

<header><nav><main><footer> 的结构，任何接手代码的人都能在 5 秒内理解页面布局；而 .wrapper > .inner > .box1 > .content 的 div 嵌套则需要读懂 CSS 才能猜测结构意图。语义化是给人看的文档。

4. 浏览器默认行为

部分语义标签带有内建的无障碍角色和行为，无需额外代码：<button> 自带键盘聚焦和 Enter/Space 触发；<details>/<summary> 原生实现折叠；<dialog> 处理焦点陷阱（focus trap）。用 <div> 模拟这些行为，需要写大量 ARIA 和 JS 来补齐。

四、面试中容易被追问的点 ​

article vs section 的区别：<article> 是独立的、可脱离页面单独存在的内容单元（一篇博客文章、一条评论、一个产品卡片）；<section> 是有主题的分区，依赖上下文才有意义。判断标准：把这块内容放到 RSS 订阅里，还有意义吗？有就用 <article>。

header/footer 可以出现多次：它们不只是页面级的，<article> 内部也可以有自己的 <header> 和 <footer>，代表文章头部和尾部。

语义化不等于不用 div：纯布局容器（Flexbox/Grid 的包裹层）用 <div> 完全正确，不需要强行找语义标签。原则是：有语义意图时用语义标签，纯布局目的时用 <div>。 <b> vs <strong>，<i> vs <em>：<strong> 表示重要性，<em> 表示语气强调；<b> / <i> 在 HTML5 中表示无语义倾向的样式偏移（粗体/斜体），与「重要 / 强调」区分。辅助技术对 <strong> / <em> 往往有更重读法，但不要指望与视觉一一对应。
